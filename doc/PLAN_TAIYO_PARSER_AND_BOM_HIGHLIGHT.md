## Часть 1. Парсер TAIYO — `TMK107BBJ106MA-T`

### 1.1 Что сломано сейчас

```
TMK107BBJ106MA-T   -> None      (падает в regex, остаётся неразобранным)
JDK107BBJ226MA-T   -> None      (-> тип OTHER, не CAP)
LMK105BJ105KV-F    -> None
TMK316ABJ106KD-T   -> None
```

Реальные номера из официального каталога и дистрибьюторов парсятся только
частично — работает лишь узкий срез `JMK|TMK` + `BJ` без лишних букв.

### 1.2 Источник истины — официальный каталог

`doc/info/DOC012627480.pdf` (Taiyo Yuden, каталог MLCC, 26 стр.). Извлечён
текст, страницы 2–3 дают структуру **PARTS NUMBER**:

```
J  M  K  3 1 6  △  B J 1 0 6  M  L  -  T
①  ②  ③   ④    ⑤  ⑥ ⑦     ⑧  ⑨  ⑩ ⑪
```

| Позиция | Смысл | Коды |
|---|---|---|
| ① | **Rated voltage** | `P`2.5 `A`4 `J`6.3 `L`10 `E`16 `T`25 `G`35 `U`50 `H`100 `Q`250 `S`630 `X`2000 |
| ② | Series name | `M`=MLC, `V`=high-freq, `W`=LW reverse |
| ③ | End termination | `K`=plated, `S`=Cu internal |
| ④ | Dimension (L×W) | `063`0201 `105`0402 `107`0603 `212`0805 `316`1206 `325`1210 `432`1812 |
| ⑤ | Dimension tolerance | пусто (standard) или `A` |
| ⑥ | **Series code** | `BJ`=B, `B7`=X7R, `C6`=X6S, `C7`=X7S, `LD`=X5R, `SD`=standard, **`BBJ`**=X5R |
| ⑦ | Nominal capacitance | `104`0.1µF `105`1µF `106`10µF `107`100µF (EIA-3) |
| ⑧ | Capacitance tolerance | `F`±1% `G`±2% `J`±5% `K`±10% `M`±20% `Z`+80/−20% |
| ⑨ | Thickness | `K`0.45 `A`0.8 `D`0.85 `F`1.15 `G`1.25 `L`1.6 `N`1.9 `Y`2.0 `M`2.5 |
| ⑩⑪ | Special code / packaging | `-T` reflow, `-F` wave |

### 1.3 Ключевая находка: **напряжение — это первая буква**

`TMK107BBJ106MA-T`: `T` → **25V**. Именно это и написано в вашем BOM
(`MLCC_10UF_20%_25V_X5R_…`).

Правило подтверждается на всех номерах, которые парсер уже разбирает:

| PN | ① | парсер сейчас | по datasheet |
|---|---|---|---|
| `JMK212BJ226MG-T` | J | 6.3V (захардкожено) | 6.3V ✓ |
| `UMK105CH120JV-F` | U | 50V | 50V ✓ |
| `EMK105B7223KV-F` | E | 16V | 16V ✓ |

Совпадение случайное: «6.3V» в ветке JMK захардкожено и работает только
для префикса `J`. Для `T`/`L`/`E`/`U` текущий код дал бы неверное напряжение.

**Отдельно про `BBJ`:** в каталоге 2018 года его нет (`BBJ count: 0`) — код
новее. Значение `BBJ = X5R` подтверждено тремя независимыми источниками:
каталогом производителя не подтверждается, но **Octopart** даёт
`10uF / 25V / X5R / 0603 / 20%`, и это в точности совпадает с описанием
в вашем BOM. Каталог при этом даёт структурную часть (`BBJ` = series code
в позиции ⑥, толщина `A`=0.8 мм — совпадает с `0.8MM+0.2MM` в BOM).

### 1.4 Изменения в `src/pn_original/taiyo_mlcc_capacitor.py`

1. **Новая таблица `_VOL_BY_LEAD`** по ① из каталога (полная, 12 значений).
2. **Префикс**: `^[P A J L E T G U H Q S X]MK` вместо `^[JT]MK`.
   Вторая буква — `M`/`V`/`W` (②), третья — `K`/`S` (③).
   Реальных серий в каталоге: `TMK JMK LMK EMK` (+ `VMK`/`WMK` для high-freq).
3. **Серия-код** позиция ⑥: `BJ | BBJ | B7 | C6 | C7 | LD | SD` → диэлектрик:
   `BJ→X5R` (сохраняем текущее поведение), `BBJ→X5R`, `B7→X7R`,
   `C6→X6S`, `C7→X7S`, `LD→X5R`.
4. **Размер** ④ расширить до кодов каталога: `063→0201`, `105→0402`,
   `107→0603`, `212→0805`, `316→1206`, `325→1210`, `432→1812`.
   Убрать несуществующий в каталоге `315` (у каталога `316`).
5. **Ёмкость** ⑦: 3 цифры EIA через `pf_eia_3_to_str` (уже используется) —
   `106` → `10uF`. Сохранить поддержку 4-значного блока вида `B7105`
   (старые EMK/LMK: ведущая цифра = напряжение), но напряжение брать из ①,
   а не из отдельной таблицы `_VOL_EMK_LEAD`, если ① даёт значение.
6. **Допуск** ⑧: расширить `_TOL_FROM_LETTER` (сейчас `J K M F G Z`) — это
   покрывает `%`-коды из каталога; `A/B/C/D` (pF-класс) оставить как есть.
7. **Хвост** после допуска: толщина ⑨ и special ⑩ игнорировать (regex не
   анкорится в конце, как сейчас) — толщину в вывод не тащим, чтобы не
   ломать существующие тесты.

Целевой вывод `parse()`:
```
TMK107BBJ106MA-T -> "0603_10uF_25V_X5R_20%"
TMK316ABJ106KD-T -> "1206_10uF_25V_X5R_10%"
LMK105BJ105KV-F  -> "0402_1uF_10V_X5R_10%"
JMK212BJ226MG-T  -> "0805_22uF_6.3V_X5R_20%"   (без регрессии)
```
После `reformat_cleaned_pn` (шаблон corpus) это даёт
`0603_10uF_X5R_20%_25V`.

### 1.5 Верифицированные спецификации (LCSC, 2026-10-01)

Все проверены по LCSC в реальном браузере:

| MPN | Package | Cap | Tol | Voltage | Temp Coef | → наш вывод |
|---|---|---|---|---|---|---|
| `TMK107BBJ106MA-T` | 0603 | 10uF | ±20% | 25V | X5R | `0603_10uF_25V_X5R_20%` |
| `TMK316ABJ106KD-T` | 1206 | 10uF | ±10% | 25V | X5R | `1206_10uF_25V_X5R_10%` |
| `LMK105BJ105KV-F` | 0402 | 1uF | ±10% | 10V | X5R | `0402_1uF_10V_X5R_10%` |
| `JDK107BBJ226MA-T` | 0603 | 22uF | ±20% | 6.3V | X5R | `0603_22uF_6.3V_X5R_20%` |

Отсюда:

1. **`BBJ` → X5R** подтверждён. Ровно совпадает с описанием в вашем BOM.
2. **`BJ` → X5R** подтверждён (`TMK316ABJ106KD-T` = X5R). Значит оставляем
   `X5R`, несмотря на формулировку «B (−25…+85 °C)» в каталоге 2018 года —
   вендор в каталоге не маркирует диэлектрик по X-коду, дистрибьюторы
   маркируют `BJ` как X5R. Регрессии не будет.
3. **`JDK` — реальная серия**, существует и продаётся (LCSC: 1 результат,
   0603 / 22uF / ±20% / 6.3V / X5R). Её нет в каталоге 2018 года, но она
   старая и массовая. `J` = 6.3V по правилу ① — согласуется.
   **Прежняя догадка, что `JDK` синтетический, была неверной** — в плане
   вопрос снят, префикс добавляем.

Значит `tests/test_parser_corpus_treatment.py:84` с `JDK107BBJ226MA-T`
переедет с regex-пути на vendor-путь. Ожидаемый результат
`0603_22uF_X5R_20%_6.3V` совпадает с тем, что даёт `parse()` + шаблон
corpus, поэтому тест должен остаться зелёным — проверить обязательно.

### 1.6 Серии и префикс

Каталог даёт ②`M`/`V`/`W` + ③`K`/`S`, но `JDK` использует `DK`. Поэтому
префикс задаём **явным списком наблюдаемых серий**, а напряжение всегда
берём из ①:

```
TMK JMK LMK EMK JDK VMK WMK     (+ ① из _VOL_BY_LEAD)
```

Именно так надёжнее, чем пытаться описать вторую-третью букву одним классом:
структура позиции ②③ в каталоге относится к старым сериям и на `JDK`
не распространяется.

### 1.7 Чего НЕ делаем

- Не трогаем `PARSER_PRIORITY` (65) — конфликтов не ожидаем.
- Не добавляем толщину в вывод (меняет формат у всех потребителей).

### 1.8 Тесты

- `datasheet/taiyo_mlcc_capacitor.md` — добавить строки в таблицу `## samples`
  (это источник для `tests/test_parser_generated.py`):
  `TAIYO/TMK107BBJ106MA-T | CAP | 0603_10uF_X5R_20%_25V | vendor`
- `tests/test_pn_vendor_verified_rules.py` (стиль exact-equality) — по одному
  assert на каждую верифицированную строку из §1.5, плюс регрессии
  `JMK212BJ226MG-T`, `UMK105CH120JV-F`, `EMK105B7223KV-F`.
- `tests/test_clean_component.py` — `TMK107BBJ106MA-T` в кейсы рядом с
  существующим `TAIYO/TMK107BJ105KA-T` (проверка пути `vendor`/`pn`).
- Обязательно перепроверить `test_p1_hv_cap_and_package_retention`:
  строка с `JDK` теперь идёт через vendor, а не regex.

## Часть 2. Highlight в табе BOM

### 2.1 Задача

Чекбокс **Highlight** + поле ввода. Пользователь пишет `DIP THT` → все строки,
где эти подстроки есть **в любой колонке**, подсвечиваются. Только подсветка:
пользователь сам решает, что удалять. Контекст — SMT-only линия.

По вашему `bom.xlsx` (лист SKU3) подстрока `DIP|THT` даёт **20 строк**, и все
20 — реальные THT: пиновые разъёмы (`PIN Header_…`, `WTB CON_…`), джэки
(`Audio jack…_DIP`), SATA/HDMI/USB-коннекторы, RTC-батарейка. Ложных
срабатываний нет. Поэтому режим — **подстрока, все колонки, регистр не важен**.

### 2.2 Модель — переиспользуем существующий паттерн

Прецедент в репозитории — `CleanPreviewTableModel` в `src/qt_models.py:534`:
подкласс `SortableTableModel`, переопределяет `_get_background`, переключение
через сеттер, который эмитит `dataChanged` по всей сетке.

`PandasTableModel` уже маршрутизирует `BackgroundRole` → `_get_background()`
(`qt_models.py:450`), у `SortableTableModel` он возвращает `None`.

Изменения в `src/qt_models.py`:
- `SortableTableModel`: `set_highlight_tokens(tokens) -> int` (возвращает
  число подсвеченных строк) + переопределение `_get_background`.
- Кэш: `frozenset` индексов строк. Инвалидация в `update_dataframe()` и
  `sort()` — сортировка переставляет `_df`, кэш индексов устаревает.
  Пересчёт ленивый, при первой отрисовке после инвалидации.
- Цвет — янтарный, с учётом зебры `row % 2 == 1` (как в `CleanPreviewTableModel`).
  `BackgroundRole` перекрывает и зебру, и селекцию — это ожидаемо.

### 2.3 Важно: не помечать рабочую копию «грязной»

`bom_tab.py:126` сейчас:
```python
self.bom_model.dataChanged.connect(lambda *args: self._mark_working_dirty("bom"))
```
Эмит `dataChanged` только с `BackgroundRole` (перерисовка подсветки) сейчас
**помечал бы BOM как изменённый** и запускал автосейв. Это главный подводный
камень фичи.

Фикс: заменить лямбду на обработчик, который смотрит роли:
```python
def _on_bom_data_changed(self, top, bottom, roles):
    if QtCore.Qt.ItemDataRole.DisplayRole in roles or \
       QtCore.Qt.ItemDataRole.EditRole in roles:
        self._mark_working_dirty("bom")
```
То же для PnP (`pnp_tab.py`).

### 2.4 UI — левая панель таба BOM

Новая группа `QGroupBox` после `gb_bom_file`:
- `switch_checkbox("Highlight")` (`ui/chrome.py:65`);
- `QLineEdit` с placeholder, например `DIP THT`;
- тултип с пояснением, что это подсветка, а не фильтр.

Ввод: `textEdited` → дебаунс 400 мс → обновить токены + пересчитать.
Чекбокс вкл/выкл — просто включает/выключает подсветку, токены сохраняются.
Счётчик найденных строк пишем в консоль:
`BOM Highlight: 20 of 266 row(s) match 'DIP THT'` — в существующий
`_log(...)`, как и предупреждение о пропавшем листе.

### 2.5 Сохранение настроек

Зеркалим `separator`/`sheet`:

  сохранённых ранее);
- продублировать в профиль: `profiles.py` → `_gather_profile_payload["bom"]`
  и `_apply_profile_payload`.

### 2.6 i18n

Новые ключи во **всех 6** `lang/*.json` (`test_ui_i18n.py:25` требует точного
равенства наборов ключей):
`bom.highlight`, `bom.highlight_tip`, `bom.highlight_tokens`.

### 2.7 Тесты

Стиль — `tests/test_clean_preview_model.py` (роли Qt) и
`tests/test_bom_pnp_window_load.py` (MainWindow + изолированный `QSettings`):

- `BackgroundRole` = `QBrush` для совпавшей строки, `None` для несовпавшей;
- `DIP` матчит `..._DIP_2` (подстрока, не точное равенство);
- регистр не важен; несколько токенов через пробел = OR;
- пустые токены → подсветки нет;
- **регрессия**: включение/выключение подсветки не ставит `_bom_dirty`;
- сортировка не ломает подсветку (кэш сброшен);
- round-trip `QSettings` для токенов.
